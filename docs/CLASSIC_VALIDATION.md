# Classic 发行验证

版本：v0.3.0-classic.1；日期：2026-11-14。

## 保留范围与源码身份

基于正式旧线路 0.3.0+sm120.2 的实际安装 wheel 导出。236 个 Python 模块全部保留；235 个逐字节相同，doctor.py 仅将深度自检的 Qwen token 预算从 64 对齐到正式冻结的 2048，避免诊断请求被严格准入拒绝。资源预测清单绑定公开模型元数据；没有放宽依赖、模型或预算保护。其余差异是独立安装/接口适配、公开清单与许可证资料。完整模型下载清单包含 13 项，合计 14,700,742,038 字节；不含新视觉串行候选。

## 本机实际验证

- Windows x64 / RTX 5070 Ti SM120；固定 Python、Paddle CUDA 12.9 和隔离 Qwen 环境。
- 完整公开源码与 wheel 内容逐字节匹配，236 个 Python 模块；全部模型本地文件已按清单 SHA256 校验。固定上游 revision 与 Apache-2.0 声明已逐项核对。
- 合成自有 DOCX、IMAGE、扫描 PDF 经受管 CLI 完成。DOCX 为 CLEAN；IMAGE/PDF 均完成 B200＋Qwen 筛选，各留 7 项待审。管理器记录进程退出完成。
- 上述三类转换使用诊断修复前的公开 wheel；最终 wheel 的转换模块与之逐字节相同。诊断修复后另执行最终安装 wheel 的完整 deep doctor：所有能力项 PASS，9 个 Paddle 模型及 OvisOCR2/Xiaomi 的加载/推理检查通过。
- 图像归属、边缘裁剪、源图渲染、安装回归通过；下载与筛选接口回归通过；新增精确依赖、子项失败拒绝和 Windows 启动共享冲突测试通过。
- 最终 wheel 的官方 MCP SDK 测试通过 auto / legacy 两种启动模式，12 个工具接口及视觉门控协议通过。
- 安装器的运行档案检查验证 Python、依赖 METADATA/RECORD/加载器、源码身份；总 READY_FULL 不能掩盖能力子项失败。

## 验证边界

本机转换测试复用经哈希确认的模型和既有依赖，不能宣称全新机器从零下载/冷安装已完成。完整系统安装涉及 LibreOffice 和 VC++ 运行库的管理员确认；本次没有完成该冷安装认证，截图 DOCX 的 LibreOffice 分支没有新增实测。发布包含对应安装步骤和完整代码。

小型转换和接口检查不是整本教材的准确率、零误删或任意输入资源认证。图片转写、公式分歧与正文待审须由具备视觉能力的调用宿主处理，不因发布成功而自动通过内容验收。当前固定档案只认证上述设备范围，其他硬件需独立验证。

GitHub Actions 的当前结果见仓库 Actions 页面；CI 验证公开字节清单、无 GPU 安装/接口回归，不冒充 GPU 全链质量测试。
